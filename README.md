# FakeLoc

**虚拟定位模块**：选点、粘贴或手输坐标，把假位置作用于你指定的应用。

> ⚠️ **仅供合法用途，风险自负** —— 完整条款见文末[免责声明](#免责声明)。

## 功能

| 功能 | 说明 |
|---|---|
| 在地图上选点 | 腾讯底图，拖图钉 / 搜地址 / 点图反查，选完统一换算成 WGS-84 |
| 坐标输入 | 纬度 / 经度，六位小数；**不做坐标系换算**，输入什么就是什么 |
| 常用位置 | **最近**（每次改锚点自动记录，坐标与地址一起存）、**收藏**（点星标固定，不会被挤掉）、八个内置城市 |
| 场景预设 | 步行 / 驾车 / 室内静止，一次设定精度、速度与漂移三个互相牵制的参数 —— 手凑的组合本身就是指纹 |
| 使用真实定位 | 以当前位置为起点（需要定位权限，受 5 秒节流保护） |
| 粘贴坐标 | 从剪贴板识别坐标、Google 地图链接、`geo:` URI、`?lat=&lng=` 参数；入口在坐标框下方 |
| 生效范围 | 固定为 **LSPosed 作用域内的全部应用**，App 里不再提供选择 |
| 信号微调 | 精度 / 海拔 / 速度 / 步行漂移，设置页默认打开的那一页；四个开关各写清关掉之后不下发什么 |
| 假地址 | 城市 / 省 / 区跟着假坐标走（地图 SDK 反查，含 adcode 与城市编码），可单独关掉 |
| 企业微信打卡 | 改写企业微信自带的腾讯定位 SDK（`…sapp` 分支）的坐标、地点名、地址与地点列表，地图、地点 chip 与打卡记录保持一致 |
| 反检测 | 抹掉 `isFromMockProvider` / `isMock` / AppOps / SettingsProvider 的 mock 标记；可**锁定原始定位源**（切断 WiFi 扫描、基站信息与原始 GNSS）—— 这是「地图先跳到模拟点、几秒后又跳回真实位置」的正解 |

## 使用方法

### 1. 安装

从 [最新 Release](https://github.com/Cobylinweiqi/FakeLoc/releases/latest) 下载
`FakeLoc-<版本>-release.apk`，或在 LSPosed 管理器的「在线仓库」里搜 **FakeLoc** 直接装。

包名是 `io.github.cobylinweiqi.fakeloc`。APK 用本项目专用密钥签名，**自己编译出来的包签名不同，
两者不能互相覆盖安装** —— 更新请始终走 Release。更早的 `com.amo.fakeloc` 是另一个 App，
如果你装过，需要先卸载。

### 2. 在 LSPosed 里激活

1. **启用 FakeLoc** 模块
2. **配置作用域**（这一步决定它到底管不管用）：
   - 默认的 `android` 与 `com.android.providers.settings` 负责反检测的全局部分，建议保留
   - 再把你想要伪造定位的 App 逐个勾上
3. 重启设备，或至少重启目标 App
4. 打开 App，界面顶部不再显示「未连接到 LSPosed 服务」即表示握手成功

> **只勾目标 App 时，Google Play 服务的融合定位（fused）拿到的仍是真坐标** —— 那个位置是 GMS
> 在自己进程里算出来的。两个解法任选：把 `com.google.android.gms` 也加进作用域（轻量，推荐先试）；
> 或者打开「系统级 hook」并把 `system` 加进作用域（覆盖最广，代价是作用域内所有 App 都被改写）。

> **生效范围只有 LSPosed 这一处。** 模块用 LSPosed 的作用域当唯一名单：勾了谁就改谁，
> 一个 App 都不用在这里重复选择。App 里那张卡只是把这句话写出来，没有开关。

### 3. 配置地图 Key（可跳过）

选点页的底图是腾讯地图，**包里不含任何 Key**，自己去
[腾讯位置服务](https://lbs.qq.com) 申请（免费额度够个人用），填进**设置页 → 地图配置**。
控制台要填的**包名与 SHA-1** 在设置页各有一条可复制（官方 Release 的证书 SHA-1 是
`28a3a1d6f8a0d9b00af1a33a70586cc0c20a04b0`，自编译的包不一样）。

三道关缺一不可，任何一道没过都是「地图能画、地址解析不出」：

- **两套授权**：同一把 Key 要同时勾 Android SDK 与 WebService API 的「逆地址解析」。
- **接口额度**：在「配额管理」里单独给逆地址解析分配每日调用量，默认是 0（个人测试 1000 次/日足够）。
- **签名校验**：开了才需要填 SK（控制台同页可查）；没开就留空，留空即不签名。

**不填 Key 也能用**：手输/粘贴坐标、常用位置与内置城市不受影响，只是选点页没有底图。

填好后点设置页的**「测试连通性」**，它真发一次请求并翻译返回码（`111` 签名没过、`113` 没配额度、
`199` 没启用 WebServiceAPI、`190` Key 无效 —— 这四种失败在选点页长得一模一样）。Key 默认只显示首尾各 4 位。

### 4. 用起来

**状态卡里的主按钮**启动 / 停止，运行中也能改参数。首页状态卡上的三个 chip 显示当前的精度 / 海拔 / 漂移值 ——
停止状态下它们会灰掉，因为那时一个都不生效。

**锁定定位源**（默认开）会切断目标 App 的 WiFi 扫描、基站信息与原始 GNSS。带着自研引擎的 App
（高德这类）靠它才能被挡住「自己再算一个真实位置」这条路。代价是那个 App 失去基于 WiFi / 基站的
室内定位能力 —— 如果它因此报「定位失败」，把这个开关关掉即可。

这一组开关都在**设置页 → 信号微调 → 反检测**里，共四个。每关掉一个，它下面会直接写出后果；
其中**接管地图 SDK** 与 **同步伪造地址** 两个在关闭前还会再确认一次 —— 它们失效时的共同特征
是「界面看着像没生效」：首页坐标仍是假的，App 拿到的却是真的。

### 5. 企业微信打卡

企业微信的定位不走系统 `LocationManager`，而是自带腾讯定位 SDK 的一个**改包分支**
（`com.tencent.map.geolocation.sapp`）。只 hook 系统层时，打卡页的地图会一直停在真实位置 ——
不是「跳一下就回弹」，而是压根没被改过。1.10.0 起这条分支也在作用范围内：

1. 在 LSPosed 作用域里勾上 **企业微信** —— 生效范围只有这一处，App 里不用再选一次
2. 重启一次企业微信
3. 先用选点页选好位置 —— **地址要一起反查成功**，打卡 chip 上的地点名与地址都从这里取
4. 打开「打卡」，地图、地点名、地址与最终记录应当同时是假位置

这一层改写的是 SDK 自己发布的结果：坐标、地点名（`getName()`）、地址（`getAddress()`）、
省市区街道，以及「选择地点」列表里每一行的名称、地址与坐标。打卡记录与地图因此不会一半真一半假。

**WiFi 打卡 / 蓝牙打卡是另外两种打卡方式**：前者比对 BSSID / SSID，后者靠信标，两者都不读定位，
本模块不覆盖。**只伪造位置，不伪造网络指纹。**

如果打卡页报「定位失败」，先关掉「锁定定位源」再试：企业微信的 SDK 在室内常常要靠 WiFi / 基站
才能算出第一个点，输入被切断时它会直接给不出结果。

### 6. 已知限制

- **反检测不等于隐身。** 它只抹掉 mock 标记；做多源交叉验证的 App（真 GPS 与网络定位对不上、
  传感器与轨迹不符）仍可能看出异常。
- **原始 NMEA / GNSS 观测数据**只在系统级作用域开启时才被压制。只勾目标 App 时，
  `addNmeaListener` 之类仍能拿到与假坐标矛盾的真实卫星数据。
- **Wi-Fi / 基站指纹完全没做** —— 要对抗基于 BSSID 的定位，那部分得自己加。
- **`system` 作用域下是本机全量伪造**，包括 FakeLoc 自己的「使用真实定位」按钮。
- 功能开关只在运行中的进程生效，**新增作用域内的 App 需要重启目标 App** 一次。
- **加固包（梆梆 / SecNeo、爱加密这类）的 App，地图通道可能晚一步才装上。** 这种包的真实 dex 由壳在
  `attachBaseContext` 里解密，模块最早能解析类的时刻还看不到 `com.baidu.location.*`。1.10.0 起会在
  App 创建完成后再装一次，并在约 1.5 / 5 / 15 / 45 秒各重试一次；日志里先出现
  `xxx SDK not reachable … will retry`、随后出现 `Baidu channel armed`，就是这条路径在起作用。
  如果只剩前者，说明 SDK 在解壳后的另一个 ClassLoader 里，把该 App 重启一次再看。
- 选点页**需要联网**（底图瓦片与地址查询都走 HTTPS）。地址查询用你填的那个 Key：**没勾「逆地址解析」，或开了「签名校验」却没填 SK，都会解析不出城市名** —— 页面底部会直接说。失败原因会进 logcat，tag 是 `FakeLoc/MapLookup`，带着腾讯返回的 status。
